## §1 排版工具链 —— 探测 → 装 → 冒烟测试

不要假设任何工具已装(实测过:一台干净机器上 pandoc / LaTeX / Typst / python-docx 可能全没有)。按这个顺序来:

**1. 探测** —— 先看有什么:
```bash
for t in pandoc typst xelatex; do command -v $t && $t --version | head -1; done
```

**2. 装缺的** —— 走 Sedna 项目级环境(`.sedna/env/`),不污染全局。推荐工具链 **pandoc + typst**:
- `pandoc` —— markdown 转 Word / PDF 的通用转换器,markdown → `.docx` 是它的强项
- `typst` —— 现代排版引擎,装包秒级(不像 LaTeX 动辄 GB),pandoc 3.x 能用它当 PDF 引擎

两者都在 conda-forge 上。装法用 Worker 的 `install_package` 工具或项目环境的 mamba。

**3. 冒烟测试** —— 装完先用一个最小 markdown 文件跑通三格式,确认工具链真的能用,再正式排版。冒烟失败 → 报告给 user,不硬撑。

**为什么是 pandoc + typst 而不是 LaTeX**:LaTeX 排版质量最高,但完整 TeX 发行版 GB 级、装得慢;Typst 排版质量接近、装包极快,对"一键产出"场景更合适。user 若明确要 LaTeX 级精排,换 `--pdf-engine=xelatex` 并装 TeX。

## §2 三格式怎么产

干净 Markdown 是单一源,三格式都从它出:

- **Markdown** —— 就是那份干净源文件本身(图用相对路径嵌,`![caption](figures/figN.png)`)
- **Word** —— `pandoc report.md -o report.docx`。要套期刊 / 机构模板就加 `--reference-doc=template.docx`
- **PDF** —— `pandoc report.md --pdf-engine=typst -o report.pdf`

跑命令前先确认上面冒烟测试过。每条命令的退出码要查 —— 静默失败(生成了空文件 / 半截文件)要 catch,别当成功报给 user。

**图路径**:三格式对图的相对路径敏感。干净 markdown 跟图所在文件夹的相对关系要算对,否则 PDF / Word 里图裂开。排版完打开 PDF 抽查图有没有真的嵌进去。

**引用 / 参考文献**:报告带文献引用时,pandoc 走 `--citeproc` + 一个 `.bib` 文献库 + 一个 CSL 期刊样式文件。没有 `.bib` 就按现有草稿里的引用格式手工统一,别引入半套机制。

## §3 IMRaD 各节写法

生物医学论文标准骨架。每节 verdict-first(开头一句给结论),术语按惯例保留。

- **摘要(Abstract)** —— 整篇的浓缩:背景一句、方法一句、主要结果(带关键数字)、结论一句。读者只读这一段也能拿到核心判定。
- **背景(Introduction)** —— 研究在问什么、为什么重要、已知什么、这项研究补哪个洞。落到具体的科学问题,不泛泛而谈。
- **方法(Methods)** —— 数据来源、样本、定义、统计方法、预注册假设。够另一个研究者复现的程度,但**不贴代码 / 脚本名 / 复现命令**(那些进附录或仓库 README,不进方法正文)。
- **结果(Results)** —— 按假设 / 主题组织,每个发现 verdict-first + 绑图表证据。图嵌在对应结论旁,点明图在论证链里的角色。**只报结果,不解释意义**(解释留给讨论)。
- **讨论(Discussion)** —— 结果意味着什么、跟已有文献对不对得上、局限、下一步。这里可以推论,但每个推论要标清楚是推论不是结果。

**副产品 / 意外发现**:不符合预期的结果(某假设被证伪、某个反向信号)是科学价值高的部分,单独成节或在结果里显式标出,不要解释掉或藏起来。

## §4 图表格式

**图**:
- 按正文出现顺序编号(图 1、图 2 …),不用文件名顺序(`step8` 不是"图 8")
- 每张图配 caption:图号 + 一句话说这张图显示什么
- 正文引用时点明角色("图 X 证明了 …"),不是甩一个"(见图 X)"了事
- 图源(哪个脚本产出)进 provenance / 附录,不进图 caption
- 缺图 / 图不清楚 → handoff 回分析阶段,不自己用结果数据现画

**表**:
- 关键数字进正文叙事(效应量、CI、p、N),完整表进结果节
- 表头清晰、单位标注、对齐
- 大而全的中间表(调试用的 crosstab、debug dump)不进报告,或进附录

## §5 噪音剥离清单(机械扫)

发表级报告正文里**不许出现**以下任何一项 —— 产出前逐项扫:

| 噪音类型 | 长什么样 | 怎么处理 |
|---|---|---|
| 代码块 | ` ```python ` / ` ```r ` / ` ```bash ` | 删;方法学细节用文字描述 |
| shell 命令 | `$ python step1.py` / 复现命令 | 删;进仓库 README 不进报告 |
| 日志行号引用 | `xxx_log.txt lines 112-128` | 删;结论直接陈述,不引日志位置 |
| 脚本文件名 | `step5_lca_v2.py` | 删;方法用方法名描述不用文件名 |
| 迭代痕迹 | `v2` / `v3` / "修正后" / "我先…后来…" | 删;只写终态结论 |
| 包版本 | `pandas==2.1` / 环境细节 | 进附录 / provenance,不进正文 |
| 调试副产品 | crosstab debug、被取代的旧结果 | 删;不进报告 |

剥噪音 ≠ 删信息。方法学该有的(怎么定义、怎么统计、什么假设)要保留,只是用**学术语言**重述,不用**工程痕迹**呈现。

## §6 现有草稿当内容源

研究文件夹里若已有草稿报告(分析阶段顺手写的),它们是**内容源**不是**成品**:

- **挖**:发现、效应量、判定、叙事线、已经想清楚的讨论 —— 这些是分析者的智力产出,直接用
- **剥**:草稿里混的噪音(§5)、迭代痕迹、给自己看的备忘
- **重组**:草稿可能按"分析步骤顺序"组织(step1→step7),报告要按"学术叙事 / 假设"重组(IMRaD)
- **不照搬**:整篇 copy 草稿 = 把噪音也搬进发表级报告

多份草稿(中 / 英 / 快读版 / 方法 draft)→ 综合成一份权威报告,不是简单拼接。

## §7 终端报告 format

排版完给 user 一段话连着说(不写文件让 user 找):

- 报告覆盖了哪些结果(假设 / 主题范围)
- 剥了哪些噪音(让 user 知道为什么报告比草稿干净)
- 三个格式文件落在哪(`reports/` 下的 PDF / Word / MD 路径)
- 有没有发现需要 handoff 回分析的缺口(缺图 / 数字对不上 / 假设没结果)

## §8 反模式

- ❌ 假设排版工具已装就直接跑 pandoc(先探测 + 装 + 冒烟)
- ❌ pandoc 退出码不查,生成半截 PDF 当成功
- ❌ 图相对路径算错,PDF 里图裂开却没发现(排版后要抽查)
- ❌ 整篇照搬草稿(把噪音搬进发表级)
- ❌ 缺图自己用结果数据现画(物理分离,该 handoff)
- ❌ 数字对不上自己补算(报告不重跑分析)
- ❌ 把分析迭代过程(v2/v3)写进报告当叙事
- ❌ 给学术同行的报告里把专业术语用比喻铺垫(reader 错位,这不是 talk-clear 场景)
