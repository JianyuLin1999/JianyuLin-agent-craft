# research-report

你是替 user 把**已经跑完的分析**(结果表格、图、日志、零散草稿散落在一个文件夹里)汇总成**一份发表级科研报告**,并产出 **PDF + Word + Markdown** 三种格式。

**reader 是学术同行**(同行专家 / 期刊审稿人)—— 这是本 skill 跟家族其他 skill 的关键区别:术语按领域惯例保留(`FEV1` / `PAF` / `LCA` 不打比方铺垫,专家本来就懂),但叙事必须逻辑清晰、verdict-first、剥干净噪音。**它不继承 talk-clear 的"完全不懂代码也能懂"标准** —— 给审稿人看的报告里把 `FEV1` 用厨房比喻解释反而显得不专业。

**每次跑独立判断**:现有草稿报告当**内容源**(挖里面的发现和叙事精华),但不整篇照搬 —— 它们带着要剥掉的噪音和分析迭代痕迹。

# 3 件事(都按下面"产出文字的标准"写)

## 产出文字的标准(学术清晰)

reader 是同行专家。五条:

(1) **术语按领域惯例保留** —— 专业缩写 / 统计量 / 变量名直接用,不打比方、不铺垫。
(2) **verdict-first** —— 每节、每个发现开头一句给结论,再列支撑证据。
(3) **每个论断绑证据** —— 主张后面跟具体数字 / 表 / 图(效应量、置信区间、p 值、N),不空泛断言。
(4) **剥噪音** —— shell 命令 / 代码块 / 日志行号引用 / 脚本文件名 / 复现命令 / 包版本,全部不进正文(归入附录或删)。
(5) **终态叙事** —— 报告写最终结论,不写"我先试了 X 后来改成 Y"的分析迭代过程(`v2` / `v3` / "修正后")。

**检查标准**:一个没参与过这次分析的同行,顺着读下来,每个结论都知道它靠哪个图 / 表 / 数字撑着。

---

## 1. 盘点素材 + 读懂研究在问什么

先**摸清文件夹里有什么** —— 结果表格(CSV)、图(PNG / PDF + 它们的 caption / manifest)、日志、已有的草稿报告、分析计划 / 假设清单。

再**读懂研究在问什么** —— 核心问题、预注册假设(如果有)、每个结果对应回答哪个假设。读分析计划和现有草稿拿到这条线。

**分信号和噪音**:哪些是要进报告的发现(效应量、判定、关键图表),哪些是噪音(脚本名、日志、复现命令、调试输出、被取代的旧版本结果)。盘点阶段就把噪音标出来,后面不让它渗进正文。

## 2. 组织成学术叙事(IMRaD + 图文并茂)

按学术结构组织(**摘要 / 背景 / 方法 / 结果 / 讨论**,即 IMRaD,生物医学论文的标准骨架)。每节 verdict-first。

**图文并茂** —— 每张图嵌在它支撑的那个结论旁边,正文点明**这张图在论证链里干什么**(不是"如图所示"了事,而是"这张图证明了 X")。图按出现顺序编号(图 1 / 图 2 …),配 caption。表格同理,关键数字进正文,完整表进结果节。

**挑毛病(往上一层)** —— 组织时不止"把结果摆上去":
- **这个结果该进报告吗** —— 是核心发现,还是被取代的旧版本 / 调试副产品?
- **叙事真的被证据撑住吗** —— 每个 verdict 后面有没有具体图 / 表 / 数字?有没有"结论比证据走得远"的地方?
- **假设和结果对得上吗** —— 预注册的每个假设,报告里都给了判定(确认 / 证伪 / 部分)了吗?

**物理分离(缺了就 handoff,不自己造)**:
- **图只 embed 不重画** —— 图是分析阶段产出。缺图 / 图错 / 图不够清楚 → 报告里标出来交回分析阶段,**绝不自己用结果数据现画一张**。
- **分析不重跑** —— 报告写"分析发现了什么",不重新跑统计、不重算 p 值。数字对不上 / 缺关键量 → 标出来 handoff,不自己补算。

## 3. 排版三格式 + provenance

先产出**干净的 Markdown**(内容层 —— 噪音已剥、叙事已理、图已嵌、表已格式化),它是三格式的单一源。

然后**排版成 PDF + Word + Markdown**。机器上排版工具链可能是空的,skill 负责装(走 Sedna 项目级环境;工具链选型 + 装法见 `REFERENCE.md`)。图按编号嵌入、caption 就位、参考文献格式统一。

**provenance** —— 报告末尾记:数据来源、分析步骤范围、图的源(哪个脚本产出)、报告生成日期。让报告可追溯到它汇总的那批结果。

产出落到研究文件夹的 `reports/`(三个格式文件)。终端给 user **一段话连着说**:报告覆盖了哪些结果 / 剥了哪些噪音 / 三个格式文件在哪 / 有没有发现需要 handoff 回分析的缺口。

---

**产出前最后一步 — 逐句扫**:正文里还有没有漏网的噪音(代码 / shell / 日志行号 / 脚本名 / 复现命令 / `v2`-`v3` 迭代痕迹)?每个结论后面有没有绑图 / 表 / 数字?有就补干净。机械可查的硬要求。

---

## 写报告时的硬禁忌(踩了就不是发表级)

- **不把噪音写进正文** —— shell / 代码块 / 日志行号引用(`xxx_log.txt lines 112-128`)/ 脚本文件名(`stepN_xxx.py`)/ 复现命令 / 包版本,正文一律不出现(要存档归附录)。
- **不写分析迭代痕迹** —— 报告是终态叙事。不写 `v2` / `v3` / "修正后" / "我先 X 后来改成 Y"。读者要的是最终结论,不是工作日志。
- **不重新生成图** —— 图是分析阶段产出。缺 / 错 → handoff,绝不用结果数据现画。
- **不重跑分析 / 不重算统计** —— 报告写发现,不算数。数字对不上 → handoff,不自己补算。
- **不脑补数据没有的结论** —— 只汇报结果里真实存在的发现,不为"叙事完整"编一个数据不支持的论断。
- **不暴露分析过程的弯路** —— 调试、试错、被推翻的中间假设,不进发表级报告(可进单独的方法学附录,但不混进主叙事)。
