# write-for-reader 改为按需加载场景要求

## Skill 文件怎样调整

- `SKILL.md` 从 140 行缩短为场景判断、文件路由和所有写作任务共同保留的要求。
- 外行讲解、技术调查、学术写作、PPT、工作文档和创意写作分别进入 `profiles/` 下的独立文件。
- 普通任务只加载一个 profile。混合成品最多增加一个次要 profile，主要文件决定结构。
- 长文、高风险内容和严格重写才加载 `AUDIT.md`。普通短答不携带完整检查清单。
- 版本从 0.1.0 更新为 0.2.0。

## HTML 怎样调整

- 正文主要篇幅改为分析 AI 文字令人不满的七个层面：读者起点、信息顺序、对象与因果、证据与判断、作者姿态、句式节奏和页面形式。
- 每一层分别说明常见症状、读者承担的额外工作、AI 容易出现这种写法的原因和修正步骤。
- 场景自动判断压缩成一张流程图。
- 新增二维象限图。横向表示成品需要补充多少解释，纵向表示写法受场景限制的程度；点击场景可以查看特定要求和加载文件。
- 页面末尾可以切换、复制和打开完整的多文件 Skill 包。

## 0.3.0：主文件与页面示例继续调整

- `SKILL.md` 依次说明读者判断、场景选择、内容组织和交付检查。旧版集中罗列的抽象规则被拆回具体动作，并增加一条实际提问示例。
- 主文件保持 100 行以内。学术写作、PPT、技术调查等特定要求仍由场景文件按需补充。
- HTML 中的原句和前后对比改用浅灰绿色表面。边框、等宽字体和编号负责区分原文与正文，颜色继续连接原文片段和对应批注。
- 二维图的轴标题改成图框外的单向箭头，减少四角长标签对场景点的干扰。
- 页面末尾嵌入的八个文件与仓库版本逐字同步，显示版本更新为 0.3.0。

## 0.4.0：加入 AI 指令场景并简化主文件

- 象限图加入“为 AI 写任务提示词”和“写可复用的 Skill”。横向向左表示需要更多解释，纵向向上表示写法更受限制；正确性继续作为所有场景共同的前提。
- 场景点颜色改为跟随所在象限，不再沿用旧的任务类别颜色。象限坐标、点色和背景色现在表达同一组关系。
- 象限轴改成贴近图框的完整方向线。纵向流程在卡片之间增加留白，箭头不再压住下一张卡片的边线。
- 新增 `profiles/instructions.md`，分别约束一次性提示词和可复用 Skill 的写法。
- `SKILL.md` 删除设计背景、提问示例和路由说明，改为直接列出判断、加载、写作和交付要求。页面末尾嵌入的九个文件与仓库版本逐字同步。

## 0.5.0：补充造词和反常搭配

- 二维图沿横向镜像。横轴现在向右表示需要更多解释，场景点、背景分区、颜色和方向箭头同步翻转。
- “语气与节奏”章节新增两类问题：给普通问题临时造词，以及把常见词拼成当前语境中少见的搭配。
- 增加“这一刀、踩在、落盘”的逐项批注和改写示例，并说明这些词在真实动作或准确技术语境中仍可使用。
- 原因、修改顺序和交付检查同步加入造词与词语搭配检查。
- `SKILL.md` 和 `AUDIT.md` 增加直接要求：优先使用领域既有名称和常见搭配，删除无必要的新词，避免把动作隐喻和工程行话移到抽象关系中。

## 0.6.0：二维图改用背景需求和过程需求

- 根据正文中“读者进不去”和“读者跟不上”两类困难重新选择坐标。横轴向右表示需要补充更多背景，纵轴向上表示需要展开更多过程。
- 所有场景重新定位。故障调查改为“给负责人写故障调查”，默认读者熟悉产品现象，但没有参与具体代码实现，因此位于右上方。
- 故障调查的点击说明增加正常流程、动作动机、内部名称和异常链要求。
- `profiles/investigation.md` 明确区分熟悉产品、熟悉事件和熟悉代码实现，并要求为未参与实现的读者补齐必要背景和关键动作目的。

## 0.7.0：主文件改为三组通用要求

- 主文件只保留“让读者看懂”“使用自然表达”和“忠实于事实”三组通用要求。
- 场景文件减少为学术写作、幻灯片与演讲、AI 指令和创意写作四份。普通解释、故障调查和工作文字直接使用主文件。
- 一项任务可以读取多份相符的场景文件。场景文件可以调整主文件中与该任务有关的要求。
- `AUDIT.md` 只在全面检查已有文字时读取，不再根据篇幅或风险自动加载。
- HTML 附录、场景说明和内嵌文件与 0.7.0 版本同步。
