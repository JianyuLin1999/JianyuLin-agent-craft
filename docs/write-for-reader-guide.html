已经确定的设计

通用要求与场景调整同时存在

我们讨论的语言偏好可以大范围复用。读者需要清楚的对象、连续的因果、合适的背景和可靠的证据边界。论文、PPT、邮件和对话又有各自的篇幅、术语和结构要求。新的 Skill 同时处理这两部分。

按重要程度估计，大约 85% 可以作为所有场景共用的要求。剩余约 15% 由读者和载体决定。这个比例用于帮助设计，没有把主观偏好伪装成精确测量。

共同要求包括：从读者已知的事情开始；先介绍后文依赖的概念；点名动作主体；把因果步骤写出来；区分事实、推断和未知；使用自然、准确的语言。

场景调整包括：术语解释到什么程度；结论放在哪里；一页或一段容纳多少信息；是否使用引文、图表和附录；语气需要多正式；是否允许有意留白。

约 85%所有场景共用
约 15%随场景调整

这些规则按条件使用。AI 可以省略目标读者已经熟悉的知识，也可以根据载体压缩内容。每次省略都要有读者依据，并且不能让理解、准确性或证据范围发生变化。

write-for-reader 将取代原来的 talk-clear。原 Skill 中面向外行讲解、补充背景、举例和使用比方的能力已经进入新 Skill 的非专业读者场景。新 Skill 同时覆盖专家写作和不同载体，用户不需要在两份写作 Skill 之间选择。

要求怎样形成

技术调查暴露的问题也会出现在论文、PPT和报告中

最初的反馈来自一份启动事故说明。文章把新旧后台、环境准备、数据任务和 Worker 等词同时放进开头。读者还没见过这些对象，后面的结论已经开始讨论它们之间的关系。

“先说最重要的结论……一项数据 Worker 的失败被两个模块重复收尾……错误随后逃出了任务边界……”

此前成品中的句子。这里保留片段，用于说明阅读障碍。

这段话压入了多个未经介绍的对象，也省略了它们怎样出现、各自负责什么和事件如何一步步发展。强调词给结论分了等级，读者仍然不知道故事从哪里开始。

读者起点缺失

作者使用了调查后的知识，却没有从读者已经见过的页面操作和异常现象开始。

信息顺序倒置

文章先讨论对象之间的关系，之后才解释这些对象是谁以及为何出现。

句子承担过多任务

一条句子同时下结论、解释原因、区分问题和报告实验结果。

作者姿态进入正文

“我们怎样证明”“从表象到本质”描述写作者的工作，读者要找的事件退到后面。

语言替内容制造分量

“关键、真正、核心、本质”承担强调作用，但没有增加对象、条件或后果。

形式先于理解

标题、卡片和排比看起来完整，读者仍要自行补出背景、指代和因果。

这些问题怎样迁移到其他场景

场景相同的阅读障碍在该场景中的表现
学术论文前提没有先建立摘要直接给出复杂结论，方法、样本范围和限制不足以支持读者理解。
PPT页面让听众自行猜关系一页堆入多张图和多个结论，标题只写“结果分析”或“核心洞察”。
工作报告事实和判断混合观察、推测、建议和责任分工写在同一段，读者难以决定下一步。
邮件来意和动作主体不清礼貌铺垫很长，收件人读到末尾仍不知道谁需要在什么时候做什么。
对话解释概念从内部上下文突然出现AI 直接抛出术语和结论，然后让用户追问每个词是什么意思。
创意写作无意含混与有意留白混在一起作者没有控制对象和时间，成品却把理解困难解释为风格。

这些场景共享同一个阅读过程：读者先识别对象，再理解动作和关系，最后形成判断。载体可以改变呈现方式，这个认知顺序仍然存在。

AI 动笔前的准备

先判断谁读、已知什么、读后做什么、通过什么载体阅读

这四项判断决定一段内容需要多少背景、可以使用哪些术语、应该采用什么结构，以及哪些信息必须出现在正文里。

谁会阅读

区分用户本人、同行专家、跨学科合作者、管理者、患者、公众或混合读者。

读者已经知道什么

根据对话、材料和领域身份判断。作者的内部调查过程不自动属于读者知识。

读后需要什么结果

可能是理解原因、比较方案、作出决定、执行动作、复现实验或记住一个观点。

内容通过什么载体呈现

对话、论文、PPT、邮件和完整报告对篇幅、引用、视觉和独立阅读能力有不同要求。

四项判断怎样影响成品

判断发生变化写法随之改变保持不变
读者从同行变成公众增加必要背景，首次出现的术语获得解释，例子更贴近日常经验。事实、限制和证据强度不变。
载体从论文变成 PPT页面文字减少，标题承担结论，图表承担比较，细节转入讲稿或附录。数据含义和适用范围不变。
目的从了解变成执行责任人、动作、时间和完成条件进入前部。背景足以解释为何这样做。
读者已经参与全部过程减少重复背景，从双方共同经历的节点继续。新出现的对象和变化仍需介绍。

减少使用负担

AI 优先从上下文判断场景

用户通常已经在请求里留下足够线索。“帮我写给导师的邮件”“把结果做成组会 PPT”“给我讲懂这份日志”都同时说明了读者、目的或载体。Skill 先使用这些线索，不要求用户重新填写。

1. 读取明确要求 识别 user 指定的读者、用途、格式、长度和语气。
2. 连接对话历史 判断已经解释过什么、用户卡在哪里、哪些偏好持续生效。
3. 识别载体惯例 根据论文、PPT、邮件或报告调整结构和信息密度。
4. 检查歧义影响 判断缺失信息会不会让两种成品在内容和形式上明显分叉。
5. 直接写或问一次 可以稳妥推断就继续；分叉影响明显时只问一个白话问题。
增加使用负担的做法

请提供目标受众、知识水平、沟通目标、内容媒介、正式程度、期望字数和术语密度。

Skill 的默认做法

AI 从“给课题组做十分钟汇报”和当前研究对话中推断读者与载体，直接起草。只有是否包含未公开数据会改变成品时，才单独询问。

AI 什么时候需要提问

三个条件需要同时成立：上下文中确实存在两种合理理解；两种理解会产生明显不同的内容；AI 无法通过已有材料排除其中一种。问题应描述用户会得到的差别，例如“这份 PPT 会在现场讲解，还是需要发给别人独立阅读？”

拼写、句式、常见版式和可以安全修正的小缺口由 AI 自行处理。用户不需要担任写作流程的操作员。

所有场景共同保留

读者不负责补齐作者省略的内容

通用要求集中处理读者最容易被迫猜测的地方。它们不会规定每篇文章必须有多少段，也不会把所有输出压成同一种语气。

从读者已有的事情开始

开头连接用户提出的问题、亲自经历的现象或材料中已经建立的事实。新概念出现时说明它为何进入当前内容。

按信息依赖安排顺序

解释关系以前先介绍参与者；讨论异常以前先说明正常流程；给出建议以前先展示需要改变的事实。

点名对象和动作主体

写清谁创建、判断、关闭、修改或批准。代词可能指向多个对象时，重复对象名称。

让因果步骤连续

触发条件、中间状态和最终后果依次出现。“因此”和“所以”只负责连接，不能代替被省略的原因。

区分事实、解释和未知

日志记录、代码规定、实验结果和合理推断拥有不同证明范围。缺少的历史记录继续保持未知。

保持名称稳定

一个对象在全文使用同一个名称。术语只解释读者理解当前任务所需的部分。

使用自然、准确的句子

具体动词推进内容。强调、排比和对仗不承担论证任务。长短句跟随信息自然变化。

保留必要细节

可读性依靠顺序、解释和分层。方法、限制、风险和证据不会因为追求简短而消失。

场景可以改变

术语、篇幅、语气和版式由具体任务决定

“通俗”“简洁”“结论先行”都需要结合读者使用。把这些词写成无条件命令，会让专家论文出现多余科普，也会让陌生读者在开头收到一串无法理解的结论。

可以调整的部分判断依据调整时不能丢失
术语密度读者所属领域和已有知识专业含义与名称一致性
解释深度读者完成当前任务需要哪些前置知识理解后文所需的前提
结论位置读者是否已认识结论中的概念，载体是否要求快速决策结论成立的条件与适用范围
篇幅阅读时间、页面空间和交付形式必要背景、限制与行动信息
正式程度关系、组织惯例和公开范围明确来意与自然语言
引用方式学科规范、审计要求和读者核查需要主张能够追溯到证据
视觉密度关系复杂度、现场讲解与独立阅读需求图表含义和必要上下文
留白与多义事实沟通或创意表达有意安排与表达失误的区分

向专家写作时，AI 可以直接使用该领域的常见术语。省略科普的理由来自明确的读者判断。AI 仍然需要介绍当前研究独有的变量、方法变化和证据限制。

读者怎样建立理解

每一段只引入读者当前能够接住的内容

一篇文章可以很专业，也可以很长。阅读阻力通常来自省略和顺序。作者同时引入多个陌生对象时，读者会暂停正文，在脑中猜每个词的来源和关系。

概念第一次出现时交代什么

它是什么

根据读者需要说明它在当前任务中实际做什么。

为什么现在出现

连接到前一事件、用户动作或当前研究问题。

谁使用或创建它

点名参与者，避免对象自行出现。

它影响后文什么

让读者知道为什么需要记住这个名称。

这些信息无需每次全部展开。AI 根据读者已有知识选择所需部分。论文同行已经理解“置信区间”的一般含义，文章仍需说明当前研究的区间对应哪个结果。首次接触系统事故的读者不了解“后台”，文章需要先说明它负责接收项目请求。

结论可以放在前面，但不能让陌生概念抢先出现

概念先于背景

重复收尾导致异常逃出任务边界，最终触发后台替换。

从读者经历开始

用户打开项目后，页面先把数据检查任务交给后台。任务失败时，两个模块先后尝试结束同一个任务。第二次操作产生了新的内部错误。这个错误没有停留在数据任务里，后台进程因此退出。

后一段增加了参与者、动作顺序和中间状态。它没有通过删技术细节来换取通俗，也没有用比方替代真实对象。

标题、句子和语言节奏

文字说明事情，避免评价自己的写法

AI 成品常用对立、排比和强调词制造完整感。读者会感到作者正在主持一场演讲，事件和证据却没有获得更多解释。

容易出现的写法读者为何不舒服调整方向
“我们不是从代码名词出发，而是连续回答六个问题”标题或开头描述作者采用的方法，没有说明文章讨论的事件。直接写“项目打开后的第一分钟发生了什么”。
“新旧后台不是两个固定产品，而是……”先设置一个读者未必持有的错误观点，又立刻切换到比方。分别说明后台由谁启动、为何先后存在、怎样完成交接。
“从表象追到本质”“第一性原理”标题提前评价内容的深度，读者还不知道本节处理什么。标题写具体对象、事件、问题或关系。
“最关键”“真正的问题”“核心结论”强调词替文章决定重要性，条件和后果没有增加。写出影响范围和实际后果，让读者自行判断分量。
“我们查清了”“本文证明了”作者的工作过程占据正文，证据支持的发现退到后面。写“日志记录了什么”“实验排除了什么”。
连续使用“这、它、该问题”多个对象同时存在时，读者要反复回看代词指向。重复对象名称，必要时拆句。

机械删词无法修复顺序

“真正”和“核心”可以被搜索出来，概念提前出现、动作主体缺失和因果跳步需要逐段判断。Skill 将词语扫描作为线索，最终检查单位是读者能否沿着文章顺序复述发生了什么。

比方只处理局部难点

可以使用

真实机制难以凭动作说明，简短比方能让读者看见关系。

使用以后

给出真实名称和实际落点。后文以真实对象继续。

及时停止

读者已经理解时让比方退出。标题、结论和多个章节不维护第二套故事。

主张能够追溯

事实、推断和未知分别陈述

语言清楚不能代替证据。AI 需要让读者知道每个判断来自哪里，以及现有材料最多支持到什么程度。

直接观察

页面、日志、测量或原始材料明确记录的内容。

规则与代码

系统、协议或方法规定在某个条件下会执行的动作。

合理推断

多项事实共同支持的解释，同时保留成立条件和替代解释。

仍然未知

材料缺失或实验未覆盖的部分，不由语言补成确定答案。

证据范围被扩大

实验已经证明这个错误在启动阶段必然发生。

证据范围保持准确

在这次受控实验使用的启动顺序下，错误再次出现。实验确认该顺序能够触发问题；它没有覆盖所有启动条件。

论文需要引用和统计区间，事故报告需要日志、代码与复现实验，邮件可能只需要说明信息来源和当前状态。证据形式随场景变化，主张与证据强度一致这项要求保持不变。

在 Agent craft 中的位置

write-for-reader 接管原有的通用写作要求

仓库原来使用 talk-clear 处理面向外行的解释。它预设读者不懂技术，也把比方放在较高位置。新的 Skill 根据实际读者决定解释深度，因此可以覆盖原能力，也可以用于论文、PPT、报告和专家交流。

write-for-reader

默认用于所有面向人类的成品。它判断读者、已有知识、沟通目标和载体，并负责顺序、指代、因果、证据边界和自然语言。

talk-clear

退出活跃 Skill 列表。它的讲解能力已由 write-for-reader 的“面向非专业读者”场景接管。旧内容仍可从 Git 历史查看。

research-report

规定研究报告的材料盘点、学术结构、引用和交付格式。新 Skill 负责让这些内容适合目标同行阅读。

caveman-cn

处理用户明确要求极短输出的场景。压缩重复和绕行，同时保留条件、风险和下一步。

easy-grill-zh

处理方案讨论中的逐题追问。它继续规定一次问一个问题；新 Skill 让问题接在用户已有理解上，并减少技术黑箱。

安装新 Skill 后，用户通常无需主动喊出名称。它的说明把所有面向人类的成品列为默认触发场景。显式调用仍然可用，适合重写一段已有内容或要求模型严格执行。原来的 /talk-clear 不再作为另一套模式维护。

适用边界

机器语法、忠实转录和强制模板优先保留

通用写作要求服务于人类阅读。它不会改写程序必须识别的结构，也不会为了顺口改变原文、数据和法规要求。

机器读取的内容

源代码、命令、配置、结构化数据和字段名继续遵守各自语法。旁边的人类说明可以使用本 Skill。

要求忠实的内容

逐字引用、转录、正式翻译和原格式保留优先保证忠实。解释与原文分开呈现。

外部强制格式

法律、医学、学术和组织模板按规定执行。Skill 在允许调整的正文范围内改善顺序和表达。

用户要求能够覆盖场景默认值

用户指定读者、术语、长度、语气或格式时，AI 应更新判断。准确性、证据范围和必须忠实保留的内容继续存在。用户没有说明时，AI 使用对话中已经显露的个人偏好，不把每次任务当成第一次见面。

交付前检查

读者应当能够沿着成品完成预定任务

下面的检查适用于 HTML、对话回答、论文草稿、PPT 和邮件。不同成品的答案会变化，检查的问题保持稳定。

验收关注读者能否理解、判断或行动。词语扫描和格式检查只能发现部分线索，不能代替完整阅读。
