真实反馈

让人不满的地方分布在整篇文章的不同层面

下面四条反馈表面上分别指向标题、开头、句式和语气。继续往下拆，会看到读者知识、文章顺序、对象关系和作者姿态同时出了问题。单独换几个词只能缓解表面症状。

“我们不是从代码名词出发，而是连续回答你提出的六个问题”

标题在说明作者采用了什么写法。读者打开文章时想知道事件内容，这个标题没有提供对象、动作或问题。

涉及三层问题

作者姿态进入标题；先设置一个没有必要的对立；方法说明占据了内容标题的位置。

“先说最重要的结论……数据 Worker 的失败被两个模块重复收尾……”

一句话里出现 Worker、模块、收尾、任务边界和后台。它们都来自调查后的内部知识。读者还不知道这些对象怎样进入故事，也不知道动作顺序。

涉及五层问题

读者起点错位；信息依赖倒置；对象未经介绍；因果链被压扁；强调词替事实决定重要性。

“新旧后台不是两个固定产品，而是同一研究值班室的前后两班人”

句子先纠正一个读者未必持有的观点，随后又要求读者理解一套值班室比方。真实后台的创建、交接和退出仍未出现。

涉及四层问题

虚构对立；比方抢在事实前面；真实对象被替换；读者需要同时维护技术系统和比方系统。

“还有很多上价值、下判断、喊口号的内容”

文章不断告诉读者哪些内容最深、最关键、最接近本质。事件后果和证据没有承担这些判断，作者的声音因而压过材料。

涉及三层问题

证据与判断脱节；作者自我评价；语言节奏被口号、排比和结论预告控制。

这些不满共享一个结果：作者把本应写在纸面上的关系留给读者猜。读者需要自行补背景、认对象、排时间、接因果、判断证据，还要抵抗作者不断发出的重要性指令。

问题之间的关系

同一段文字可以同时在七个层面失效

前四层决定读者能否理解内容，第五和第六层决定文章是否像一个人在认真说明事情，第七层决定页面能否帮助读者找到关系。上游没有修好时，下游润色只能让混乱变得更顺口。

第一层读者起点文章是否从读者已经知道的事情开始，新概念是否有进入故事的理由。
第二层信息顺序前提、对象和事件是否在被使用以前出现，多条问题线是否得到分开。
第三层对象与因果谁做了什么、状态怎样变化、一个结果怎样走到下一个结果。
第四层证据与判断观察、代码、实验、推断和未知是否拥有相符的语气与结论范围。
第五层作者姿态正文是否在说明事情，还是在展示作者多会分析、多有洞察。
第六层句式与节奏词语、句长、转折和段落是否自然，是否反复出现模型常用模板。
第七层页面形式标题、卡片、颜色、表格和图是否承担真实关系，还是只制造完成感。

阅读时从第一层向下建立理解；修改时也应从第一层开始。先做句式润色会掩盖仍未解决的结构缺口。

第一层：读者起点

AI 从自己掌握的全量材料开始写，读者只能看到成品

AI 在写作时已经读过代码、日志、对话和调查结论。它容易把这些信息当作共同背景。读者没有经历这段内部过程，第一段里的每个内部名称都会形成新的理解负担。

这一层的常见症状

概念凭空出现

后台、环境、Worker、任务边界等名称没有来源，也没有说明当前为何需要它们。

背景从作者经验开始

文章从调查者已经形成的架构图开始，忽略用户实际看到的页面和操作。

解释数量与读者无关

面对专家仍重复常识，面对新读者又直接使用内部词。

读者被迫完成什么工作

读者需要暂停当前句子，猜一个词属于程序、进程、任务还是角色。多个新词同时出现时，读者还要猜它们之间的层级。猜测一旦错误，后面的因果关系会全部建立在错误地图上。

作者已经知道全部结构

第二套后台未接管时，数据 Worker 已越过环境准入并触发异常收尾。

从用户实际经历开始

用户打开项目后，页面仍然连接着此前启动的后台。页面同时准备新的运行环境。系统原本要等新环境可用，再把后续请求交给新的后台。

修正办法
  1. 列出读者亲自见过的操作、页面现象和错误提示。
  2. 第一段只使用这些内容，以及一个得到立即解释的新对象。
  3. 每个新概念第一次出现时，说明它是什么、为何此时出现、后文为什么需要它。
  4. 解释深度由目标读者决定。专家共同知识可以省略，当前事件独有的对象不能省略。

第二层：信息顺序

后一句依赖的知识，需要在前一句出现

文章的顺序不能只跟随作者想到结论的顺序。读者需要先认识参与者，再理解参与者之间的关系；先看到正常流程，再判断异常发生在哪里。

这一层的常见症状

结论抢在概念前面

开头给出压缩后的根因，结论中的词要到后文才获得解释。

多条问题线挤在一起

后台退出、环境竞态和退出时重生同时出现，读者无法判断它们是否属于同一因果链。

背景与当前问题脱节

文章列出完整架构和调查过程，却没有说明哪些背景服务于眼前的问题。

为什么“结论先行”会在这里失效

结论可以提前出现，前提是读者已经认识结论中的对象。把最终调查结论原样搬到开头，只是把作者的终点放到了读者的起点。读者必须先记住一串暂时无法理解的词，随后再回头修改这些词的含义。

文章任务需要先出现随后才能讨论
说明后台为何退出后台负责什么、谁启动它、正常情况下怎样结束任务哪一步产生了错误，错误怎样离开任务范围
说明新旧后台交接为什么会启动第二套后台、接管的完成条件旧后台为何仍在服务，第二套为何尚未接管
说明数据摸排竞态数据任务何时产生、环境准备何时开始两条工作如何重叠，谁打断了谁
提出修正方案现状、原因、约束和仍然未知的范围哪些改法能够覆盖问题，代价是什么
修正办法

先为每一节写出它要回答的具体问题，再列出回答这个问题必须知道的前提。前提仍未出现时，把解释移到前面。两条线可以分别完整复述时，先分开叙述；直到关系得到证据支持，再把它们连接起来。

第三层：对象与因果

读者需要知道谁做了什么，变化怎样一步步发生

抽象名词、被动语态和代词能够把多步过程压成一句话。句子变短了，读者承担的推理却变多了。技术调查、论文和项目报告都会因此出现“好像有结论，但说不清过程”的感觉。

这一层的常见症状

动作没有执行者

“发生收尾”“完成切换”“触发接管”没有说明哪个模块执行动作。

代词跨越多个对象

连续出现“它、这、该问题”，任何一个都可能指向进程、任务或错误。

连接词替代中间过程

句子使用“所以、因此、随后”，触发条件和状态变化仍然缺失。

一句话为什么会显得莫名其妙

“一项数据 Worker 的失败被两个模块重复收尾，第二次收尾产生内部冲突，错误随后逃出了任务边界，带走了整个后台。”

这句话包含至少五个动作：任务失败、模块一结束任务、模块二再次结束任务、第二次操作报错、错误离开任务处理范围、后台进程退出。作者把动作压进一个句子后，谁执行了哪一步、第二次操作为何发生、错误为何能够离开任务范围都消失了。

名词化压缩

重复收尾造成异常逃逸并触发后台替换。

参与者和状态逐步出现

数据任务先报告失败。负责调度任务的模块随后把它标记为结束。另一个模块又尝试结束同一个任务，第二次操作产生了新的错误。任务处理代码没有接住这个错误，后台进程因此退出。

修正办法

为每个关键句标出“执行者—动作—对象—状态变化”。一句话包含多个主要动作时拆开。因果链至少写出触发条件、中间变化和后果。代词可能指向两个对象时，直接重复名称。

第四层：证据与判断

材料能支持到哪里，结论就写到哪里

语言流畅会让推断看起来像事实。AI 还容易把一次复现扩写成普遍规律，把时间接近扩写成因果，把缺失日志留下的空白补成确定动机。

四种内容需要不同语气

直接观察

日志、页面、测量和原始材料确实记录了什么。

规则与代码

当前实现规定在某个条件下会执行什么。

合理推断

多项事实共同支持的解释，以及它成立所需的条件。

仍然未知

历史记录缺失、实验没有覆盖或材料相互冲突的部分。

强调词为什么会加重问题

“最关键、真正、核心、本质”常常出现在证据尚未展开以前。它们先替读者完成了重要性判断。文章如果没有写出影响范围、失败后果和替代解释，这些词只增加作者确信的声音。

实验范围被扩大

真实客户端实验已经证明退出阶段存在必然的后台重生问题。

结论停在实验覆盖范围

在这次客户端退出实验使用的顺序下，桌面应用关闭后又启动了一套后台。实验确认该顺序可以触发重生；其他退出顺序尚未覆盖。

修正办法

每项判断旁边注明它来自观察、代码、实验还是推断。先写证据显示什么，再写作者如何解释。缺少记录时说明缺口会限制哪些结论。需要表达重要性时写出实际影响，让读者根据后果判断。

第五层：作者姿态

文章说明事情，作者的分析过程退到幕后

AI 常用“我们将、我们发现、我们证明、接下来从三个层面”等句子维持篇章秩序。这些句子让作者持续站在读者和内容之间，也容易形成主持稿和汇报腔。

作者姿态过重的几种形式

写法它在做什么读者缺少什么修正方向
“我们怎样证明这些根因”展示调查者的方法本节具体处理哪些证据改为“六项实验分别排除了哪些解释”
“从表象追到本质”提前评价内容深度本节的对象和问题改为具体事件或因果问题
“这不是 A，而是 B”先替读者设置错误观点A 是否真实存在、B 的条件是什么分别说明 A 缺少的条件和现有材料支持的关系
“先说最重要的结论”要求读者接受优先级重要性来自什么后果直接陈述结论、范围和影响
“我们终于查清了”强调作者完成工作证据究竟显示什么让日志、代码或实验成为句子主语

比方为什么也可能成为作者表演

比方适合处理一个难以直接看见的关系。它一旦进入标题、结论和多个章节，读者需要记住真实对象与比方对象的双重映射。比方越生动，越可能抢走本应属于事实的注意力。

修正办法

标题写对象、事件、问题或关系。正文直接写材料显示什么。方法过程只有在读者需要判断可信度或复现时出现。比方完成局部解释后给出真实名称，随后淡出。

第六层：句式与节奏

自然语言没有固定拍子，也不会每段都制造转折

很多 AI 痕迹来自重复的句法节奏：先否定、再转折、再用三个并列项展开、最后用一句口号收尾。单段看起来完整，连续阅读时会像套用同一个模具。

常见的节奏问题

连续使用对立句

每段都通过否定 A、宣布 B 来推进，文章不断制造并不存在的争论。

长句塞入多条线

括号、分号和连接词不断增加，句子直到末尾才出现主要动作。

短句像日志条目

句子虽然短，相邻句没有关系词和状态承接，读者仍要自行组织。

抽象名词堆叠

准入、收口、终态、边界、闭环等词一起出现，具体动作消失。

同义反复

段落用三个近义句重申同一个判断，信息没有推进。

口号式结尾

最后一句追求整齐和力度，条件、风险与未知被压掉。

删掉“AI 词”仍然难读的原因

词语只是线索。第一段同时引入五个陌生对象时，删除“核心”和“真正”不会恢复背景。因果链缺少中间步骤时，把长句拆成四个短句也不会自动产生关系。

修正办法
  1. 先确认句子在整段中的任务，再修改词语。
  2. 用具体动词替换抽象名词组合，施动者靠近动作。
  3. 一个句子承载一个主要动作，条件较多时先写条件，再另起一句写结果。
  4. 长短句跟随信息变化。默读一遍，检查真人是否会用同样节奏连续说三段。
  5. 删除没有增加对象、条件、证据或后果的重复句。

第七层：页面形式

卡片、颜色和图表需要承担明确的阅读关系

HTML 很容易把每段话放进卡片，再用多种颜色制造层次。页面看起来经过设计，连续阅读却被不断切断。视觉元素如果没有表达比较、顺序、层级或状态，只会增加扫描目标。

页面形式怎样掩盖内容问题

卡片代替分段

本可连续解释的内容被切成许多小块，读者需要自行恢复段落关系。

颜色代替证据等级

绿色让推断看起来已证实，红色让普通限制看起来像严重事故。

图表代替选择

所有信息都被可视化，真正需要比较的关系反而没有获得突出。

选择视觉形式前先问什么

信息关系适合的形式不需要视觉化时
多个对象横向比较表格或对齐卡片只有一个对象时写连续段落
状态随时间变化时间线只有一次变化时写前后两句
层级、所有权或嵌套树状图层级只有两层时直接点名关系
多个因素位于连续维度坐标图或散点图只有两个固定选项时使用短对比
分支和条件路径流程图线性步骤使用编号列表
修正办法

先用文字说明页面要表达的关系，再选择最小可用形式。颜色只表示已经定义的状态。卡片只用于并列对象。正文需要连续推理时保持连续，不为了“丰富”而切碎。

生成机制

AI 为什么反复产生这些写法

这些问题不等于模型缺少词汇。模型在组织信息、预测常见文章形态和压缩上下文时，会自然滑向几种稳定模式。Skill 需要干预这些模式，不能只提供一张禁用词表。

模型同时看见全部材料

它容易从最终理解状态开始写，把自己刚读到的内部信息当作读者背景。读者起点因此消失。

局部句子比全篇依赖更容易优化

每句话可以语法完整，章节之间仍然缺少前提顺序。模型需要明确检查后文依赖是否已在前文出现。

熟悉的修辞模板容易生成

否定—转折、三段并列和口号收尾在训练文本中很常见。它们能够快速产生“像文章”的外形。

压缩常发生在错误位置

模型删掉背景、条件和中间过程，却保留作者预告、强调词和格式性段落。字数减少，推理负担转移给读者。

确信语气能够遮住证据缺口

当材料不完整时，强烈的判断词会让段落显得稳定。稳定感不能增加证据，反而让未知范围更难发现。

页面组件容易制造完成感

卡片、标签和颜色可以快速形成层次。模型若没有先判断信息关系，视觉层次会与内容结构脱节。

修正顺序

从读者起点开始重建，再处理句子和页面

重写需要先修上游。读者模型、证据边界和信息依赖确定以后，句子才有稳定的内容可以表达。下面的顺序适用于技术报告、论文解释、PPT 文稿和一般长文。

重建读者起点

写下读者亲自经历过什么、已经读过什么、没有理由知道什么，以及读完后要完成什么。删除作者内部调查过程形成的默认知识。

整理事实、推断和未知

在写正文前确定每项材料能够支持到哪里。存在记录缺口时先划定未知范围，避免后续叙事为了流畅自动补全。

建立信息依赖顺序

每节只回答一个具体问题。列出回答它需要的对象和前提，确保这些内容已经在前文出现。独立问题先分开。

展开对象、动作和状态变化

点名执行者、动作、对象和结果。将压缩成抽象名词的过程恢复为读者能够复述的步骤。

清理作者姿态和句式模板

标题改成实际内容。删除自我评价、虚构对立、预告深度和无依据的强调。随后调整句长、动词和段落连接。

选择必要的页面形式

只有比较、时间、层级、坐标或分支关系需要视觉表达时才加图。连续推理保留连续正文。最后在真实屏幕上完整阅读。

读者验收

成品需要让首次接触内容的人完成预定任务

验收不看作者是否覆盖了所有规则。它检查读者能否沿着文章形成正确理解，并据此判断或行动。

Skill 的运行方式

场景判断在内部完成，只加载当前需要的规则

这部分只说明 Skill 怎样减少使用负担。用户不需要填写表格，也不需要在多个写作 Skill 之间选择。

读取请求和历史识别 user 已给出的读者、材料、偏好和成品类型。
判断四项信息读者、已有知识、读后任务、呈现载体。判断留在内部。
加载一个 profile选择解释、调查、学术、PPT、工作或创意中的一个主要文件。
必要时补一层混合成品再加一个次要 profile；长文或高风险内容加载 AUDIT。
交付自然成品不展示路由、规则和评分。缺少关键信息时只问一个实际差别问题。

写作场景二维象限

读者的已有知识与行动压力共同改变写法

横轴表示作者和读者共享多少背景知识，纵轴表示成品需要推动决定或行动的程度。点击图中的场景，可以查看代表性读者、沟通任务和特定要求。位置表达常见情况，具体任务仍会因用户上下文移动。

通俗解释

共享背景少 · 主要任务是建立理解

典型读者第一次接触主题、只见过表面现象的人
成品要完成补齐必要背景，让读者理解对象、过程和结论

渐进式披露

主文件负责路由，场景要求按需进入上下文

加载规则

普通任务：主文件 + 一个 profile。
混合任务：主文件 + 一个主要 profile + 一个次要 profile。主要文件决定结构。
长文或高风险任务：在上述文件之外加载 AUDIT.md，进行五轮检查。
明确禁止：为了显得完整一次加载全部 profile。

例如，学术会议汇报以 presentation.md 决定页面结构，再由 academic.md 补充术语、数据和证据要求。普通工作邮件只加载 workplace.md。
